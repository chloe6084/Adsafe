# AdSafe 검수 — 실사이트 테스트 가이드

검수 엔진 정리 및 이벤트 룰 DB 이전 완료 후, **실제 사이트에서 검수 기능을 테스트**하는 방법입니다.

---

## 1. 사전 준비

### 1.1 서버 실행

- **XAMPP**에서 **Apache**를 시작합니다.
- (선택) MySQL이 로컬에 있다면 **MySQL**도 시작합니다.  
  Aiven 등 원격 DB를 쓰는 경우 MySQL 서비스는 필요 없습니다.

### 1.2 DB·API 설정

- **api/.env**  
  - DB 연결 정보(DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME)가 설정되어 있어야 합니다.  
  - Aiven 사용 시 `DB_SSL_CA`(CA 인증서 경로)도 설정합니다.
- **시드 실행** (최초 1회, workspace·user·risk_taxonomy·rule_set_versions·rules 필요 시)  
  ```bash
  php api/scripts/seed.php
  ```
  (프로젝트 루트에서 실행. Node·npm은 사용하지 않습니다.)
- **이벤트 룰 3건**  
  - 이미 적용했다면 생략.  
  - 아직이라면 `docs/sql/seed_event_rules.sql`을 DB에서 실행해 활성 룰셋에 3건 INSERT합니다.

### 1.3 API 동작 확인

브라우저에서 다음 주소를 엽니다.

- **http://localhost/AdSafe/api/health**

`{"ok":true}` 또는 비슷한 응답이 보이면 API가 동작하는 것입니다.

---

## 2. 검수 페이지 접속

### 2.1 URL

- **검수 화면**: **http://localhost/AdSafe/adsafe.html**  
  (XAMPP 기본 경로가 `htdocs\Adsafe`라면 위 주소로 접속됩니다. 실제 배포 경로에 맞게 `/AdSafe` 부분을 조정하세요.)

### 2.2 로그인

- 검수/이력이 **로그인 필요**로 되어 있다면, 먼저 **로그인**합니다.  
  시드 사용자 예: `admin@adsafe.com` / `Admin123!` (환경에 따라 다를 수 있음)
- 로그인 없이 검수만 열어 두었다면, 해당 페이지만 열면 됩니다.

---

## 3. 검수 실행 방법

1. **광고 문구 입력**  
   - adsafe.html 상단의 **텍스트 입력란**에 검수할 문구를 넣습니다.
2. **「검수하기」 클릭**  
   - 버튼 클릭 시 `POST /api/inspect`로 문구가 전송되고, 서버(PHP)에서 룰이 적용됩니다.
3. **결과 확인**  
   - **요약**: 리스크 레벨(없음/낮음/보통/높음), 적발 건수, 안내 문구.  
   - **검수된 문구**: 문제 표현 하이라이트.  
   - **상세 리스크 항목**: 각 적발 건의 리스크 이름(API의 level3 또는 fallback), 레벨, 매칭 표현, 설명, 수정 가이드.

---

## 4. 이벤트 룰 테스트 문구 (Phase B 검증)

이벤트 룰 3건이 DB에 들어가 있다면, 아래 문구로 각각 동작을 확인할 수 있습니다.

| 테스트 | 입력 문구 예시 | 기대 결과 |
|--------|----------------|-----------|
| **할인 50% 이상** | `60% 할인`, `50% 이상 할인 이벤트` | RISK_PRICE_EXCESSIVE, **높음**, 매칭 표현에 "50% 이상" 등 |
| **할인율 미기재** | `할인 이벤트 진행 중`, `특가 세일` (숫자% 없음) | RISK_PRICE_EXCESSIVE, **보통**, "할인율 미기재" |
| **이벤트 기간 미표기** | `이벤트 진행 중`, `선착순 할인` (기간/날짜 없음) | RISK_INDUCEMENT_CONDITION, **높음** 또는 **보통** |

- 여러 문구를 한 번에 넣어도 됩니다.  
- 결과에서 **리스크 이름**이 API에서 내려준 **level3**로 표시되는지 확인하면, CTO 보고서의 "표시 API 기준 통일" 검증에 해당합니다.

---

## 5. 검수 이력 확인

1. **이력 목록**  
   - **http://localhost/AdSafe/inspection-history.html**  
   - 방금 실행한 검수가 목록에 보이는지 확인합니다.
2. **이력 상세**  
   - 목록에서 항목을 클릭해 상세 화면으로 들어갑니다.  
   - **rule_set_version_id**, **rule_id** 가 DB에 저장된 환경이라면, 상세 API/DB에서 해당 run과 findings에 값이 채워져 있는지 확인하면 Phase B 저장 검증이 됩니다.  
   - (프론트 이력 상세 화면에 rule_id를 직접 표시하는 컬럼이 없을 수 있으므로, 필요 시 브라우저 개발자 도구 > Network에서 `GET /api/inspection-history/:id` 응답을 보거나 DB에서 `inspection_runs`, `inspection_findings` 테이블을 조회해 확인할 수 있습니다.)

## 6. 문제 해결

| 현상 | 확인 사항 |
|------|-----------|
| **검수하기 눌러도 반응 없음** | F12 > Console에 에러가 있는지 확인. Network에서 `POST /api/inspect` 요청이 나가는지, 4xx/5xx인지 확인. |
| **API 연결 오류** | 주소가 `http://localhost/AdSafe/...` 인지 확인. `ADSAFE_API_URL`이 다른 값으로 덮여 있지 않은지 확인. |
| **이벤트 룰이 안 잡힘** | DB에 이벤트 룰 3건이 **활성 룰셋**에 INSERT되어 있는지 확인. `rule_set_versions.status = 'active'` 인 버전에 대해 `rules` 테이블에 `event_numeric_50`, `event_combo_discount_missing`, `event_combo_period` pattern이 있는지 확인. |
| **이력에 안 남음** | `POST /api/inspect` 응답에 `saveError`가 있는지 확인. DB 연결, `api/.env`, 시드(workspace·user 등) 실행 여부 확인. |
| **리스크 이름이 코드/이상함** | API 응답의 `findings[].level3`가 채워져 있는지 확인. 비어 있으면 프론트 fallback 맵으로 표시됩니다. |
