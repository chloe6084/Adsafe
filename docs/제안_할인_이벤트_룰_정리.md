# 할인·이벤트 룰 — 현재 동작 정리 & 의료법 기준 개선안

---

## 1. "가격이 나오면 조건(대상/기간/횟수/부가비용)이 함께 있는지" — 지금 어떻게 체크되나?

### 결론: **조건(대상/기간/횟수/부가비용)은 따로 체크하지 않습니다.**

현재 엔진이 하는 건 아래 세 가지뿐입니다.

| 체크 항목 | 현재 로직 | 비고 |
|-----------|-----------|------|
| **할인율** | `할인|이벤트|특가|반값|무료` 가 있는데 **"숫자% 할인/이벤트/오프"** 패턴이 없으면 → **"할인율 미기재"** (medium) | 정가→할인가(금액)만 있는 경우는 보지 않음 |
| **50% 이상 할인** | `N% 할인/이벤트/오프` 중 N≥50 이면 → **RISK_PRICE_EXCESSIVE** (high) |  |
| **이벤트 기간** | `이벤트|할인|특가|프로모션` 이 있는데 **(기간 패턴 없음)** 또는 **(선착순|한정|오늘만|…) 있음** → **RISK_INDUCEMENT_CONDITION** (기간 미표기/조건부 혜택) | 기간 패턴: `2024.1`, `1월`, `~까지`, `기간`, `종료` 등 |

**전혀 안 하는 것:**
- 가격(원화)이 나왔을 때 **대상(어떤 시술/진료)** 가 함께 있는지
- **횟수**(1회/5회권 등) 명시 여부
- **부가비용**(마취·약·재진료 별도 등) 안내 여부
- “정가 → 할인가”처럼 **금액이 둘 다 있으면 할인율 대신 인정**하는 예외

그래서 **“가격 나오면 조건(대상/기간/횟수/부가비용) 체크”는 현재 구현되어 있지 않습니다.**

---

## 2. "300만원 → 100만원 할인"이 할인율 미기재로 뜨는 이유

현재 규칙은 다음과 같습니다.

- **할인율 있다고 인정하는 경우**: 문구 안에 **`숫자 + % + (할인|이벤트|오프)`** 가 있을 때만 (예: `30% 할인`, `50% 이벤트`).
- **300만원 → 100만원 할인**에는 **%가 없음** → “할인율 미기재”로 판단함.

의료법/운영 관점에서는 말씀하신 대로,

- **정가·할인가가 둘 다 있으면** 소비자가 할인 폭을 알 수 있으므로,
- **할인율(%)을 반드시 적으라고 할 필요는 없음.**

즉, “할인율 미기재” 룰을 **“% 없고, 정가→할인가(금액)도 없을 때만”** 걸리도록 바꾸는 게 맞습니다.

---

## 3. 의료법 기준 — 할인·이벤트 쪽에서 챙기면 좋은 것

교수님 자료 + 의료법 제56조(비급여 진료비용 할인/면제 광고를 속이거나 오인하게 하면 안 됨)를 기준으로 정리하면 아래와 같습니다.

### 3-1. “오인·속이기” 방지 — 필수로 보면 좋은 정보

할인/이벤트를 내걸 때 **있으면 좋고, 없으면 “검증 필요”로 플래그**해도 될 항목입니다.

| 항목 | 설명 | 현재 |
|------|------|------|
| **기간** | 이벤트/할인 기간(시작~종료) | ✅ 기간 패턴 있으면 RISK_INDUCEMENT_CONDITION 완화 |
| **대상** | 어떤 시술/진료에 적용되는지 | ❌ 미체크 |
| **할인율 또는 금액** | N% 할인 **또는** 정가→할인가 | ⚠️ N%만 인정, 정가→할인가 미인정 |
| **부가비용** | “추가 비용 없음” 단정 시, 실제로 마취·약·재진료 등 별도 없음인지 | ❌ 미체크 |

### 3-2. 제안하는 룰 구조 (할인·이벤트)

- **목표**: “거짓/오인” 확정이 아니라 **“조건이 불명확하면 검증 필요”** 플래그.

| 구분 | 제안 로직 | 리스크 코드/메시지 |
|------|-----------|---------------------|
| **1) 할인율 vs 금액** | 할인/이벤트/특가 키워드가 있을 때, **“N% 할인”** 이 있거나 **“정가(숫자+만원/원) → 할인가(숫자+만원/원)”** 패턴이 있으면 → 할인율/금액은 “있다”고 간주. 둘 다 없을 때만 **“할인율·금액 미명시”** (기존 “할인율 미기재” 대체 또는 세분) | RISK_PRICE_EXCESSIVE 또는 별도 RISK_INDUCEMENT_VAGUE |
| **2) 기간** | 이벤트/할인 있는데 **기간(날짜, ~까지, N월, 기간 한정 등) 없음** → “이벤트 기간 미표기” | 기존 RISK_INDUCEMENT_CONDITION 유지 |
| **3) 조건부(선착순 등)** | 선착순/한정/오늘만 등 있는데 기간·대상이 불명확 → “조건부 혜택, 기간·대상 명시 권장” | 기존 RISK_INDUCEMENT_CONDITION 유지 |
| **4) “추가 비용 없음” 단정** | “추가 비용 없음/전혀 없음/별도 비용 없음” 등 **단정 표현** 있음 → “부가비용(마취·약·재진료 등)이 실제로 없을 수 있으니 검증 필요” | 신규 RISK_PRICE_DECEPTIVE (교수님 제안 반영) |
| **5) 50% 이상 할인** | N% 할인 중 N≥50 → 고위험 (조건·기간 명확해도 주의) | 기존 RISK_PRICE_EXCESSIVE 유지 |

“가격이 나오면 **조건(대상/기간/횟수/부가비용)** 이 함께 있는지”는, 위 표에서  
- **기간** = 이미 일부 체크  
- **대상/횟수/부가비용** = **현재는 체크 안 함** → “대상(시술/진료) 미명시”, “추가 비용 없음 단정” 정도만 단계적으로 넣는 걸 제안.

---

## 4. 구현 제안 (승인 후 반영 가능)

### 4-1. “할인율 미기재” 보완 — 정가→할인가 인정

- **조건**: `할인|이벤트|특가|반값|무료` 등이 있고, **“N% 할인/이벤트/오프”** 가 **없을 때**만 아래를 추가로 확인.
- **추가 확인**: 문구에 **정가와 할인가가 둘 다 있는지** (예: `\d+만\s*원?\s*[→\-~]\s*\d+만`, `정가\s*\d+`, `할인가\s*\d+` 등).
- **판단**:
  - **정가→할인가(금액)가 있으면** → “할인율 미기재” **내지 않음** (할인율 없어도 됨).
  - **%도 없고 금액 비교도 없으면** → 기존처럼 “할인율·금액 미명시” (또는 “할인율 미기재”) 플래그.

이렇게 하면 **“300만원 → 100만원 할인”** 은 할인율 미기재로 안 뜨게 할 수 있습니다.

### 4-2. “조건(대상/기간/횟수/부가비용)” 체크 확장 (단계적)

- **1단계 (우선)**  
  - 기간: 현재 유지.  
  - 할인/이벤트 시 **할인율 또는 정가→할인가** 인정 (위 4-1).  
  - “추가 비용 없음/전혀 없음” → RISK_PRICE_DECEPTIVE(또는 기존 코드에 “추가 비용 단정” 플래그) 추가.
- **2단계 (선택)**  
  - “대상 미명시”: 할인/이벤트 있는데 **시술명·진료명**이 전혀 없으면 경미한 “대상 명시 권장” 플래그. (키워드/정규식으로만 하면 오탐 많을 수 있어서 선택.)

**요약**: “가격 나오면 조건 체크”는  
- **지금**: 기간만 일부 보고, **대상/횟수/부가비용은 안 봄.**  
- **제안**: 1단계에서 **기간 + 할인율 또는 금액(정가→할인가) + “추가 비용 없음” 단정** 까지 반영하고, “300만원 → 100만원 할인”은 할인율 미기재로 안 나오게 조정.

## 5. 정리

| 질문 | 답 |
|------|----|
| 가격 나오면 **조건(대상/기간/횟수/부가비용)** 체크되나? | **아니요.** 지금은 **기간**만 간단히 보고, 대상/횟수/부가비용은 보지 않습니다. |
| “300만원 → 100만원 할인”이 할인율 미기재로 뜨는 이유? | **“N% 할인”만 인정**하고 있어서, **정가→할인가(금액)** 는 “할인 정보 있음”으로 보지 않기 때문입니다. |
| 의료법 기준으로 어떻게 하면 좋나? | **할인율 또는 정가→할인가** 둘 중 하나만 있으면 “할인 정보 있음”으로 두고, **기간** 유지, **“추가 비용 없음” 단정**은 별도 플래그, **대상/횟수/부가비용**은 2단계에서 선택 반영** 하는 걸 제안합니다. |

원하시면 다음 단계로 **4-1(정가→할인가 인정 + 할인율 미기재 완화)** 부터 구체적인 패턴 예시와 PHP 수정 포인트까지 적어드리겠습니다.
