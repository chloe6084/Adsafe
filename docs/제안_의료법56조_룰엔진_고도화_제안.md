# 의료법 제56조 기반 룰 엔진 고도화 제안

> 교수님 참고 자료를 바탕으로, AdSafe 서비스에 **반영할 만한 항목**만 정리했습니다.  
> **승인해주시면** 해당 항목만 순차 반영하겠습니다.

---

## 1. 현재 AdSafe vs 교수님 자료 비교

| 구분 | 현재 AdSafe | 교수님 자료 |
|------|-------------|-------------|
| **법 조항 매핑** | 암묵적 (룰만 있음) | 제56조 ②항 금지유형 → Rule 명시적 매핑 |
| **검출 방식** | 키워드 포함 + 정규식 단독 | **근접 검출**(극단 수치 + 성과지표 N자 이내) |
| **위험도** | 룰별 고정 high/medium/low | **점수 합산** (80+ High, 50–79 Medium, 20–49 Low) |
| **프레이밍** | “위반” 느낌 | **“검증 필요”** (허위 확정 X) |
| **허위 수치 전용** | 50% 할인 등 일부만 | **0%/100%/99.9% + 재발률/만족도/성공률** 등 체계적 |
| **가격/할인 기만** | 할인율·이벤트 기간 | **“추가 비용 없음” 단정**, 조건 생략 검출 |

## 2. 반영 제안 (승인 대상)

### 2-1. 새 리스크 코드·룰 추가 (우선 추천)

교수님 4종 “거짓 내용 표시” 중, **현재 AdSafe에 없거나 약한 부분**만 추가합니다.

| 제안 코드 | 법 근거 | 검출 요약 | 비고 |
|-----------|---------|-----------|------|
| **RISK_FALSE_NUMERIC** | 거짓 내용 표시 | 극단 수치(0%, 100%, 99.9%) + 성과지표(재발률, 만족도, 성공률, 부작용률, 효과, 완치) **근접** 시 | 신규 |
| **RISK_UNVERIFIED_CREDENTIAL** | 자격·인증 허위 | "공식/공인/인증/지정/수상" + "전문의/병원/기관" 등 결합, **근거(기관명·인증번호) 없음** | 기존 RISK_QUALIFICATION_* 보강 |
| **RISK_UNVERIFIED_EQUIPMENT** | 장비·최초/유일 | "국내 유일/전국 최초" + "도입/보유/장비", "FDA/CE/KFDA" + "승인/안전 보장" | 신규 |
| **RISK_PRICE_DECEPTIVE** | 가격·할인 기만 | "추가 비용 없음/전혀 없음", "전 품목/모든/무제한" 할인 등 **조건 생략** | 기존 RISK_INSURANCE_FREE, 할인 룰 보강 |

- **RISK_FALSE_NUMERIC**:  
  - 1단계: 정규식으로 `(재발률|만족도|성공률|부작용률|효과|완치).{0,25}(0|100|99\.9)\s*%` 및 역순 패턴.  
  - 2단계: “통증 0”, “1회 시술로 100% 개선” 등 확장 패턴(선택).
- **RISK_UNVERIFIED_CREDENTIAL**:  
  - 키워드: 공식 인증, 공인, 인증 병원, 지정, 수상, 우수 + 전문의/병원/기관.  
  - (선택) “인증번호/기관명/연도”가 같이 없으면 플래그.
- **RISK_UNVERIFIED_EQUIPMENT**:  
  - 키워드: 국내 유일, 전국 최초, FDA 승인, CE, KFDA, 식약처 + 장비/도입/보유/안전 보장.
- **RISK_PRICE_DECEPTIVE**:  
  - 키워드: 추가 비용 없음, 전혀 없음, 전 품목 할인, 무제한, 정가 대비 (조건 없이 사용).

→ **승인 여부**: 위 4개 리스크를 **택소노미 + 룰(키워드/정규식)** 로 추가해도 될지 알려주세요.

---

### 2-2. “근접(proximity)” 검출 도입 (선택)

- **내용**: “극단 수치”와 “성과지표”가 **한 문장/일정 글자 수(예: 20~30자) 안에 함께** 나오면 HIGH로 잡는 방식.
- **현재**: 키워드/정규식이 **딱 한 덩어리**만 매칭. “재발률 0%”는 정규식으로 가능, “0% 재발” 등 순서 바뀐 것도 정규식 2개로 처리 가능.
- **제안**:  
  - 1차: **정규식 2개** (성과지표…극단수치 / 극단수치…성과지표) 로 근접 흉내 → **DB 룰만 추가**로 가능.  
  - 2차: PHP에서 “극단 수치 위치” + “성과지표 위치” 구한 뒤 거리 계산 → **엔진 로직 확장** (작업량 큼).
- **권장**: 먼저 **정규식 2개**만 추가(2-1의 RISK_FALSE_NUMERIC). 필요 시 나중에 2차 근접 로직 추가.

→ **승인 여부**: “근접”은 **정규식 2개로 1차만** 반영해도 될지 알려주세요.

---

### 2-3. 설명 문구를 “검증 필요” 톤으로 통일 (권장)

- **내용**: 적발 시 설명을 **“위반”이 아니라 “검증 필요(허위 가능성)”** 로 통일.
- **예**:  
  - 기존: “절대적 최상급 표현은 광고법상 제한됩니다.”  
  - 변경: “이 표현은 근거 제시가 필요할 수 있습니다. 인증·통계 출처를 명시하세요.”
- **범위**: `explanation_template` / `suggestion_template`(DB) 및 `rules_data.json` 문구만 수정. 로직 변경 없음.

→ **승인 여부**: 전체 룰 설명을 **“검증 필요” 톤**으로 바꿔도 될지 알려주세요.

---

### 2-4. 점수(스코어) 기반 위험도 (선택, 작업량 많음)

- **내용**: 룰별로 점수(예: 40/20/50) 부여 → 합산해서 80+ High, 50–79 Medium, 20–49 Low.
- **현재**: 룰마다 `risk_level` 고정. 합산 없음.
- **필요 작업**:  
  - DB: `rules` 테이블에 `score`(또는 `weight`) 컬럼 추가.  
  - 엔진: 매칭 시 점수 합산, 구간별로 summary level 계산.  
  - 기존 `risk_level`과 병행할지, 대체할지 결정 필요.
- **장점**: 복합 트리거(효과 보장 + 부작용 없음 + 수치)를 고위험으로 묶기 좋음.  
- **단점**: 룰/택소노미 전반 수정, 프론트 표시 방식 변경 필요.

→ **승인 여부**: **당장은 제외**하고, 2-1·2-2 반영 후 2단계로 진행할지 여부만 알려주셔도 됩니다.

---

### 2-5. 교수님 “제56조 ②항 → Rule 매핑” 문서화만 (권장, 코드 변경 없음)

- **내용**:  
  - “치료효과 오인 / 후기 활용 금지” → 기존 RISK_EXPERIENCE_*, RISK_GUARANTEE_*  
  - “비교 우위 / 비방” → RISK_COMPARISON_*, RISK_SUPERLATIVE_*  
  - “부작용 누락 / 과장” → RISK_GUARANTEE_ZERO_RISK, RISK_GUARANTEE_CERTAINTY  
  - “자격·명칭” → RISK_QUALIFICATION_*  
  - “할인/면제 오인” → RISK_INDUCEMENT_*, RISK_PRICE_EXCESSIVE  
  - “인증·보증·추천” → RISK_QUALIFICATION_*, RISK_INSURANCE_GUARANTEE  
- **방식**: `docs/` 아래에 **“의료법 제56조_룰 매핑.md”** 한 개 만들어서, 현재 룰과 법 조항을 표로 매핑.
- **효과**: 팀/교수님에게 “우리 엔진이 법 조항을 어떻게 커버하는지” 보여주기 좋음.

→ **승인 여부**: 이런 **문서만** 추가해도 될지 알려주세요.

---

## 3. 반영하지 않기로 제안하는 것

- **시술 장면/환부 노출**: 텍스트 검수만으로는 검출 불가. 이미지·영상 검수 기능이 있을 때 별도 검토.
- **기사형/전문가 칼럼형 광고**: 문맥 판별 필요. 1차 룰 엔진 범위에서는 제외.
- **심의필 문구/버전 관리**: “심의필 번호” 같은 메타데이터 검증은 현재 서비스 스코프 밖으로 보고 제외.

## 4. 진행 순서 제안 (승인 시)

1. **2-5** 문서화: 의료법 제56조 ↔ 현재 룰 매핑 문서 작성.  
2. **2-1** 신규 룰 4종: 택소노미 + 키워드/정규식 룰 추가 (DB + `rules_data.json` fallback).  
3. **2-2** 근접 1차: RISK_FALSE_NUMERIC용 정규식 2개 추가.  
4. **2-3** 설명 톤: 기존 룰 explanation/suggestion을 “검증 필요” 톤으로 수정.  
5. (선택) **2-4** 점수화: 별도 일정으로 설계·반영.
